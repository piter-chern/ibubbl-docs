iBubbl is an iMessage-first sales platform. The API lets you:

- **Send messages** programmatically from your iBubbl line.
- **Manage contacts** — create, look up, and respect opt-outs.
- **Receive events** via webhooks — inbound replies, send results, reactions, and opt-outs delivered to your server in real time.

The API is HTTPS-only, JSON-everywhere, and authenticated with a single Bearer API key. There's no SDK to install — your existing HTTP client is enough.

## Quickstart

<Steps>
  <Step title="Sign up">
    Create an account at [ibubbl-dashboard.vercel.app](https://ibubbl-dashboard.vercel.app/signup). iBubbl sets up and runs your iMessage line for you; you don't connect your own Mac or Apple ID. You need an active line from iBubbl before you can send.
  </Step>
  <Step title="Generate an API key">
    In the dashboard, open **Settings → API Access** and click **Create key**. Copy the key (format: `ib_pk_` + 64 hex characters, 70 in all). This is the only time the full secret is shown.
  </Step>
  <Step title="Send your first message">
    Put **your own mobile number** in `to`, so your first message lands on your phone.

    ```bash
    curl -X POST https://api.ibubbl.com/v1/messages \
      -H "Authorization: Bearer $IB_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "to": "+14155551234",
        "body": "Hey Sam — quick check-in about your order.",
        "idempotency_key": "a3f2c8d9-e0f1-4b4d-9c5a-7b8e2d1f0c4a"
      }'
    ```

    The response returns `202 Accepted` with the message's lifecycle state. See [POST /v1/messages](/api-reference/messages/send) for the full reference.
  </Step>
  <Step title="Subscribe to webhooks (optional)">
    Register an HTTPS endpoint to receive events as they happen — inbound replies, delivery state changes, opt-outs. See [Webhooks Overview](/webhooks/overview).
  </Step>
</Steps>

<Note>
**Testing safely.** There is no sandbox or test mode: every request is live, and every send delivers a real iMessage from your line. Lines are set up and managed by iBubbl, so there is no test line either. Send your first messages to your own mobile phone, not to customers, and use a dedicated API key for testing that you can revoke when you're done.
</Note>

## Base URL

All API requests go to:

```
https://api.ibubbl.com
```

There is no staging endpoint or test mode at this time: every request is live, and a send delivers a real message. Your dashboard account is your only environment; use a dedicated API key for each integration so you can rotate independently.
