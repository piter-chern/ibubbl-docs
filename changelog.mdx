title: 'Changelog'
description: 'Changes to the iBubbl API and these docs, newest first.'
---

**Type** says what changed: **New** is a new API capability, **Changed** is a change in how the API behaves, **Correction** means the docs were wrong and now match the API, and **Docs** is new or reorganised documentation with no API change.

| Date | Change | Type |
| ---- | ------ | ---- |
| 2026-11-13 | [iMessage lookups](/guides/check-imessage-availability) are now on for every account; you no longer need to ask for them. `404 feature_disabled` now only means they were turned off for your account. | Changed |
| 2026-11-13 | New endpoints [Look up a number](/api-reference/imessage-lookups/create) (`POST /v1/imessage-lookups`) and [Retrieve a lookup](/api-reference/imessage-lookups/retrieve): find out whether a number can receive iMessages before you send something that only works over iMessage. Answers iBubbl already has come back at once (`200`); otherwise one of your lines asks Apple (`202`, pending), and the answer arrives by GET and by the new webhook event [`imessage_lookup.completed`](/webhooks/events#imessage-lookup-completed). A subscription without an `event_types` filter receives it. Asking Apple uses a budget of 50 lookups an hour and 100 a day per line, shared with GoHighLevel Check iMessage steps; 60 requests a minute per account. New errors `404 feature_disabled`, `422 invalid_phone`, `429 lookup_budget_exhausted` and `503 lookup_unavailable`. See [Check iMessage availability](/guides/check-imessage-availability). | New |
| 2026-11-12 | A message scheduled in the dashboard now gets a preview card for its link when it fires, like a message typed there: when its text ends in exactly one `http(s)` link with no other link in it, and it has no files, `effect` or reply. Before, it always went out plain. Its [message](/api-reference/messages/retrieve) shows `link_preview: true`; the [scheduled message](/api-reference/scheduled-messages/retrieve) still shows `false`, and `link_preview: false` in an [update](/api-reference/scheduled-messages/update) doesn't remove that card. | Changed |
| 2026-11-12 | New field `link_preview` on [Schedule a message](/api-reference/scheduled-messages/create#link-preview-cards): a scheduled message can send its link as a preview card, with the same rules as [Send a message](/api-reference/messages/send#link-preview-cards). The rules are checked when you schedule and on every [update](/api-reference/scheduled-messages/update), which can now turn the card on or off. The scheduled message object, and the `scheduled_message.*` webhooks, carry `link_preview` (`false` for messages scheduled in the dashboard). See [Send a link with a preview card](/guides/schedule-messages#send-a-link-with-a-preview-card). | New |
| 2026-11-12 | New endpoint [Send a scheduled message now](/api-reference/scheduled-messages/send-now) (`POST /v1/scheduled-messages/{id}/send-now`): sends a message that is still `scheduled` in the request, and answers with it `fired` (with its `message_id`) or `failed`. Safe to call twice. It shares the 300-a-minute conversation-actions budget. | New |
| 2026-11-12 | New error `409 scheduled_message_changed`: [Update a scheduled message](/api-reference/scheduled-messages/update) when other requests kept changing it at the same moment, or [send it now](/api-reference/scheduled-messages/send-now) when another request had just moved it to later. Read it again and retry. | New |
| 2026-11-12 | [Create a webhook subscription](/api-reference/webhooks/create) now rejects body fields it doesn't take with `422 validation_error`, naming the field. Before, they were ignored, so a typo such as `events` for `event_types` created a subscription to every event type. See [Versioning](/versioning). | Changed |
| 2026-11-12 | The [OpenAPI file](/openapi) now shows `null` fields in its examples, as the API returns them (for example `removed_at` on a tapback, and the `"city": null` that clears a field on [Update a contact](/api-reference/contacts/update)); the file's generator had been dropping them. [Receive an event](/api-reference/inbound-events/receive) now describes its request body, a JSON or form-encoded object, so the API playground can send one. The inbound event size limit is 256 KiB (262,144 bytes); the docs said 256 KB. | Correction |
| 2026-11-12 | New webhook event [`conversation.line_changed`](/webhooks/events#conversation-line-changed): a conversation moved to another of your lines, because someone pressed Continue on it in the dashboard, a one-to-one message went out on another line, or the contact wrote to another of your lines. A subscription without an `event_types` filter receives it. See [When a conversation's line is no longer yours](/concepts/lines-and-routing#when-a-conversations-line-is-no-longer-yours). | New |
| 2026-11-12 | New tapback `failed_reason` value `line_inactive`: the line was paused or retired before the tapback went out. See [`message.reaction.failed`](/webhooks/events#message-reaction-failed) and [Add a tapback](/api-reference/messages/react). | New |
| 2026-11-12 | New: [scheduled messages](/guides/schedule-messages). [Schedule a message](/api-reference/scheduled-messages/create) (`POST /v1/scheduled-messages`) sends a one-to-one message at `send_at`, 1 minute to 90 days ahead, with the same content as a send; [list](/api-reference/scheduled-messages/list), [retrieve](/api-reference/scheduled-messages/retrieve), [update](/api-reference/scheduled-messages/update) (text and time) and [cancel](/api-reference/scheduled-messages/cancel) them. Opt-outs and blocks are checked again when it fires. Files are copied when you schedule. Up to 5,000 waiting per account. The dashboard's **Send later** messages appear here too. New errors `send_at_too_soon`, `send_at_too_far`, `scheduled_limit_reached`, `scheduled_group_unsupported`, `scheduled_empty`, `409 scheduled_message_sending` and `503 no_active_line`. | New |
| 2026-11-12 | New webhook events [`scheduled_message.fired`](/webhooks/events#scheduled-message-fired), [`scheduled_message.failed`](/webhooks/events#scheduled-message-failed) and [`scheduled_message.cancelled`](/webhooks/events#scheduled-message-cancelled). A subscription without an `event_types` filter receives them. | New |
| 2026-11-12 | `idempotency_key` is now one namespace for [Send a message](/api-reference/messages/send) and [Schedule a message](/api-reference/scheduled-messages/create): a key used on one returns `409 idempotency_conflict` on the other. Keys starting with `sched:` are reserved and refused with `422 validation_error`. | Changed |
| 2026-11-12 | Corrected [Send attachments](/guides/attachments#what-your-contact-sees): a PDF sent to a contact who only takes SMS/MMS doesn't fail the whole message. The caption and any images still go out, the message keeps their status, and the PDF is reported with [`message.part_failed`](/webhooks/events#message-part-failed), not `message.failed`. Seen on a real phone. | Correction |
| 2026-11-12 | The [Overview](/introduction) example used a fixed `idempotency_key`, so every copy of it after the first would replay the first message instead of sending. It now generates a new key, like every other example. | Correction |
| 2026-11-12 | [List messages](/api-reference/messages/list) now says what `sent_at` holds on a message that never went out: the time it was accepted. | Docs |
| 2026-11-12 | A line keeps its ID when it moves to another account, so a conversation can still name a line that is no longer yours. Requests that would go out through such a line are now refused with `422 no_eligible_line`: a send to an existing group (`chat_guid`), [Edit](/api-reference/messages/edit), [Unsend](/api-reference/messages/unsend), [Add](/api-reference/messages/react) and [Remove a tapback](/api-reference/messages/remove-reaction), and [Start typing](/api-reference/conversations/start-typing). Don't retry them. [Mark a conversation read](/api-reference/conversations/mark-read) still marks the messages read but sends no receipt, with the new `read_receipt_skipped_reason` value `line_inactive`. | Changed |
| 2026-11-12 | The `chat_guid` examples in [Send messages](/guides/send-messages) and [Group conversations](/concepts/group-conversations) named a real group conversation; running them could message it. They now use the fictional `any;+;00000000000000000000000000000000`, which matches no chat, and the example participants are fictional numbers. | Correction |
| 2026-11-12 | New webhook event [`message.part_failed`](/webhooks/events#message-part-failed): a message's text went out but its files didn't, so the message keeps the text's status and `message.failed` doesn't fire. Today that's a calendar invite (`.ics`) to a contact who texts by plain SMS, which can't carry one; iBubbl no longer sends an `.ics` to a contact it already knows texts by plain SMS. New `failed_reason` `sms_attachment_refused`. A subscription without an `event_types` filter receives it. | New |
| 2026-11-12 | [`message.failed`](/webhooks/events#message-failed) carries a new `error` object: `code` (the same value as `failed_reason`), a readable `message`, and `retryable`. `failed_reason` and `error_message` are unchanged. | New |
| 2026-11-12 | New endpoints for files that have no public URL: [Upload a file](/api-reference/files/upload) (`POST /v1/files`, `multipart/form-data` with one part named `file`, the same types and size limits as URL attachments), [Retrieve a file](/api-reference/files/retrieve) and [Delete a file](/api-reference/files/delete). An upload returns a file object; put its `id` (`file_…`) in `attachments` on [Send a message](/api-reference/messages/send), alone or next to `https` URLs. One upload can be sent any number of times for 24 hours (`expires_at`), then it is deleted. 60 uploads a minute and 4 at once per account; up to 500 files and 1 GiB held at once. New errors `file_not_found`, `file_expired`, `file_quota_exceeded` and `408 upload_timeout`. See [Send attachments](/guides/attachments#upload-a-file). | New |
| 2026-11-12 | Your contacts now see each file's real name, most visibly on a PDF: an upload's file name, or a URL file's `Content-Disposition` name (else the last part of its path), cleaned and with the type's own extension. Before, files arrived with a generated name. Each of a message's `attachments` has a new `filename` field with the name that was sent (`null` for received files and for files sent before this change). See [File names](/guides/attachments#file-names). | New |
| 2026-11-11 | Corrected [Lines and routing](/concepts/lines-and-routing#imessage-or-sms): it said attachments weren't part of the public API. One-to-one messages with files, including ones sent with `attachments` through the API, take the same iMessage-or-SMS decision as text. | Correction |
| 2026-11-11 | New endpoints: [List lines](/api-reference/lines/list) (`GET /v1/lines`, paginated like the other lists and on the same 120-a-minute budget, with a `status` filter) and [Retrieve a line](/api-reference/lines/retrieve) (`GET /v1/lines/{id}`). Each line has its number, `status` (`active`, `paused` or `retired`), whether it is `online`, and live `limits`: new contacts today and this hour (with `waiting` and `next_slot_at`) and messages today, each with the `limit` the line runs. New errors `line_not_found` and `503 limits_unavailable`. See [Limits and queues](/concepts/limits#the-four-limits). | New |
| 2026-11-11 | Every message object ([Send](/api-reference/messages/send), [Retrieve](/api-reference/messages/retrieve), [List](/api-reference/messages/list)) now says which of your lines it was on: `line_id` and `line_number`. `to` is unchanged (always the contact). Every `message.*` webhook now carries `line_id` too; `message.queued` already did. See [Which line a message was on](/concepts/lines-and-routing#which-line-a-message-was-on). | New |
| 2026-11-11 | New field `link_preview` on [Send a message](/api-reference/messages/send#link-preview-cards): send a link as a preview card, as on an iPhone. The body must end in exactly one link; text before it arrives as its own bubble, then the card. Your line opens the page to build the card, so don't use it on one-time or click-tracked links. The message object echoes `link_preview`. See [Send a link with a preview card](/guides/send-messages#send-a-link-with-a-preview-card). | New |
| 2026-11-11 | Corrected: messages sent through the API can now have a link preview card (with `link_preview: true`). A message with a card is two bubbles: an edit changes the text and keeps the card, and an unsend takes back both. | Correction |
| 2026-11-11 | New endpoints to change a message after it's sent: [Edit a message](/api-reference/messages/edit) (`POST /v1/messages/{id}/edit`, iMessage, within 14 minutes 30 seconds, up to 5 edits), [Unsend a message](/api-reference/messages/unsend) (`POST /v1/messages/{id}/unsend`, iMessage, within 110 seconds) and [Cancel a message](/api-reference/messages/cancel) (`POST /v1/messages/{id}/cancel`, while it's still `pending` or `queued`). New guide: [Edit, Undo Send, and Cancel Messages](/guides/editing-and-unsending), with what the recipient sees on each kind of device. | New |
| 2026-11-11 | The message object has five new fields: `edited_at`, `edit_count`, `edit_status`, `unsend_status` and `unsent_at`. A message unsent as a whole now shows `body: ""`. | New |
| 2026-11-11 | New webhook events [`message.unsent`](/webhooks/events#message-unsent) (your Undo Send, and a contact unsending a message they sent you), [`message.edit_failed`](/webhooks/events#message-edit-failed) and [`message.unsend_failed`](/webhooks/events#message-unsend-failed). A subscription without an `event_types` filter receives them. | New |
| 2026-11-11 | [`message.edited`](/webhooks/events#message-edited) now fires for edits of messages you sent (`direction: "outbound"`), from the API or the dashboard. These docs already said so, but it fired only for contacts' edits. A subscription to `message.edited` that assumes every event is a contact's should check `direction`. | Changed |
| 2026-11-11 | Edit, Unsend and Cancel share the conversation-actions rate limit (300 requests per 60 seconds per account) with tapbacks, mark read and typing. | Changed |
| 2026-11-11 | New endpoints for the things a person does in a conversation: [Add a tapback](/api-reference/messages/react) and [Remove a tapback](/api-reference/messages/remove-reaction) (`POST` / `DELETE /v1/messages/{id}/reactions`, the six iMessage tapbacks, one per message), [Mark a conversation read](/api-reference/conversations/mark-read) (sends a read receipt), and [Start](/api-reference/conversations/start-typing) / [Stop typing](/api-reference/conversations/stop-typing) (the typing dots, 10 seconds per call). New errors `invalid_target`, `sms_not_supported`, `target_unsent`, `target_partly_unsent` and `503 opt_out_check_unavailable`. New guide: [Tapbacks, read receipts and typing](/guides/reactions-read-receipts-typing), including typing while your AI writes a reply. | New |
| 2026-11-11 | New webhook event [`message.reaction.failed`](/webhooks/events#message-reaction-failed): a tapback you sent, or its removal, couldn't be sent, with `action` and `failed_reason`. A subscription without an `event_types` filter receives it. | New |
| 2026-11-11 | Every `message.*` and `message.reaction.*` webhook now carries `conversation_id`, the ID the new read and typing endpoints take. See [The `conversation_id` field](/webhooks/events#the-conversation_id-field). | New |
| 2026-11-11 | The tapback, read and typing endpoints have their own rate limit: 300 requests per 60 seconds per account, separate from the 120 for lists, with `429 rate_limited` and `Retry-After` over it. See [Rate limits](/concepts/limits#rate-limits). | New |
| 2026-11-11 | Marking a group conversation read, in the dashboard, no longer sends a read receipt. It used to land in one participant's one-to-one chat instead of the group. | Changed |
| 2026-11-11 | New endpoints complete the contacts API: [List contacts](/api-reference/contacts/list) (`GET /v1/contacts`, paginated like [List messages](/api-reference/messages/list), with `search`, `tag`, `opted_out` and `blocked` filters), [Delete a contact](/api-reference/contacts/delete) (`204`), [Opt a contact out](/api-reference/contacts/opt-out) (permanent; fires `contact.opted_out` with `source: "api"`), and [Block](/api-reference/contacts/block) / [Unblock](/api-reference/contacts/unblock) a contact. | 2026-11-11 | [Send a message](/api-reference/messages/send) with the `contact_id` of a deleted contact now returns `404 not_found`; before, it sent. | 2026-11-11 | Send files: [`POST /v1/messages`](/api-reference/messages/send) takes `attachments`, up to 10 `https` URLs of photos, GIFs, videos, PDFs or audio, for one-to-one sends (not with `effect` or `reply_to_message_id`). iBubbl downloads them when the request arrives; `body` becomes optional and is the caption, but the first message to a contact still needs one. | 2026-11-11 | List endpoints are rate limited: 120 requests per 60 seconds per account, shared by all your API keys and all lists.
