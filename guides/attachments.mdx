title: 'Send attachments'
description: 'Send photos, videos, PDFs and audio by URL or by upload, with an optional caption.'
---

Send files with a message by listing them in `attachments` on [`POST /v1/messages`](/api-reference/messages/send): an `https` URL iBubbl downloads when the request arrives, or the ID of a file you uploaded first with [`POST /v1/files`](/api-reference/files/upload). iBubbl checks each file and sends it from your line with your `body` as the caption. You can mix both in one message.

```json
{
  "to": "+14155551234",
  "body": "Here's your receipt, and a photo of your order.",
  "attachments": [
    "file_3f2c8d9e0f144b4d9c5a7b8e2d1f0c4a",
    "https://files.example.com/orders/1042/photo.jpg"
  ],
  "idempotency_key": "…"
}
```

Each item is either a file ID from an upload or an `https` URL, in any mix, and the files arrive in the order you list them.

## Send files with a caption

<Tabs>
  <Tab title="Upload a file">
    Upload the file, then send its `id`. Use this when the file is on your own system or behind a login, with no public URL. One upload can go in any number of messages for 24 hours, so upload a brochure once and send it to every contact who asks.

    <CodeGroup>

    ```bash cURL
    # 1. Upload. ";type=" sets the file's type; the name is what your contact sees.
    FILE_ID=$(curl -sS -X POST https://api.ibubbl.com/v1/files \
      --max-time 120 \
      -H "Authorization: Bearer $IBUBBL_API_KEY" \
      -F "file=@Invoice 1042.pdf;type=application/pdf" | jq -r .id)

    # One key per message: generate it once, and reuse it if you retry.
    IDEMPOTENCY_KEY=$(uuidgen)

    # 2. Send it. A file ID can sit next to URLs in the same list.
    curl -X POST https://api.ibubbl.com/v1/messages \
      --max-time 60 \
      -H "Authorization: Bearer $IBUBBL_API_KEY" \
      -H "Content-Type: application/json" \
      -d "{
        \"to\": \"+14155551234\",
        \"body\": \"Here's your invoice.\",
        \"attachments\": [\"$FILE_ID\"],
        \"idempotency_key\": \"$IDEMPOTENCY_KEY\"
      }"
    ```

    ```typescript TypeScript
    import { randomUUID } from "node:crypto";
    import { readFile } from "node:fs/promises";

    const headers = { Authorization: `Bearer ${process.env.IBUBBL_API_KEY}` };

    // 1. Upload. The third argument is the name your contact sees.
    const form = new FormData();
    form.append(
      "file",
      new Blob([await readFile("Invoice 1042.pdf")], { type: "application/pdf" }),
      "Invoice 1042.pdf",
    );
    const upload = await fetch("https://api.ibubbl.com/v1/files", {
      method: "POST",
      headers, // no Content-Type: fetch writes the multipart boundary
      body: form,
      signal: AbortSignal.timeout(120_000),
    });
    const file = await upload.json();
    if (!upload.ok) throw new Error(`${upload.status} ${file.detail?.error}`);

    // One key per message: generate it once, and reuse it if you retry.
    const idempotencyKey = randomUUID();

    // 2. Send it. A file ID can sit next to URLs in the same list.
    const res = await fetch("https://api.ibubbl.com/v1/messages", {
      method: "POST",
      headers: { ...headers, "Content-Type": "application/json" },
      body: JSON.stringify({
        to: "+14155551234",
        body: "Here's your invoice.",
        attachments: [file.id],
        idempotency_key: idempotencyKey,
      }),
      signal: AbortSignal.timeout(60_000),
    });

    const data = await res.json();
    if (!res.ok) throw new Error(`${res.status} ${data.detail?.error}`);
    console.log(data.id, data.status, data.attachments);
    ```

    ```python Python
    import os
    import uuid

    import requests

    API_KEY = os.environ["IBUBBL_API_KEY"]
    headers = {"Authorization": f"Bearer {API_KEY}"}

    # 1. Upload. The tuple's first item is the name your contact sees.
    with open("Invoice 1042.pdf", "rb") as f:
        upload = requests.post(
            "https://api.ibubbl.com/v1/files",
            headers=headers,
            files={"file": ("Invoice 1042.pdf", f, "application/pdf")},
            timeout=120,
        )
    file = upload.json()
    if not upload.ok:
        raise RuntimeError(f"{upload.status_code} {file['detail']['error']}")

    # One key per message: generate it once, and reuse it if you retry.
    idempotency_key = str(uuid.uuid4())

    # 2. Send it. A file ID can sit next to URLs in the same list.
    res = requests.post(
        "https://api.ibubbl.com/v1/messages",
        headers=headers,
        json={
            "to": "+14155551234",
            "body": "Here's your invoice.",
            "attachments": [file["id"]],
            "idempotency_key": idempotency_key,
        },
        timeout=60,
    )
    data = res.json()
    if not res.ok:
        raise RuntimeError(f"{res.status_code} {data['detail']['error']}")
    print(data["id"], data["status"], data["attachments"])
    ```

The `202` response is the usual [message object](/api-reference/messages/send#responses), with an `attachments` array describing what will be sent, in your order:

```json
{
  "id": "8b3a4e72-1c2d-4e5f-9a0b-2c3d4e5f6a7b",
  "status": "pending",
  "body": "Here are the photos from today's visit.",
  "attachments": [
    { "kind": "image", "mime_type": "image/jpeg", "size_bytes": 2481133, "filename": "front.jpg" },
    { "kind": "image", "mime_type": "image/jpeg", "size_bytes": 1975020, "filename": "back.jpg" }
  ]
}
```

(Other fields are omitted here.) [Retrieve a message](/api-reference/messages/retrieve) and [List messages](/api-reference/messages/list) return the same `attachments` array, including the files your contacts send you. They describe the files; they don't return their contents or URLs.

<Note>
**Set a 60-second client timeout on sends with URL attachments.** iBubbl answers only once every file is downloaded and stored, which can take up to about 30 seconds for large files. A send of uploaded files, or of text only, answers at once.
</Note>

## Upload a file

When a file has no public URL, upload it with [`POST /v1/files`](/api-reference/files/upload) and put the `id` it returns (`file_` and 32 hex characters) in `attachments`.

- **One file per upload,** as `multipart/form-data` with one part named `file`. Every HTTP client builds this for you: curl's `-F "file=@…"`, a `FormData` in TypeScript, `files=` in Python's `requests`.
- **The type** is the part's `Content-Type`. When that is missing or `application/octet-stream`, the file name's extension decides instead (`.mov`, `.heic`, `.mp3` …). The content must match the type: a file named `.jpg` that isn't a JPEG is refused with `422 unsupported_attachment`.
- **The same types and limits as URLs** (the table below). A file is refused as soon as it passes its limit, and nothing is stored.
- **Send it as often as you like for 24 hours.** One upload can go in any number of messages, to any of your contacts, until its `expires_at`. Each message keeps its own copy, so a sent message never depends on the upload.
- **Then it's deleted.** After `expires_at`, a send that names it returns `422 file_expired`, and [Retrieve a file](/api-reference/files/retrieve) returns `404`. To remove it sooner, [delete it](/api-reference/files/delete).
- **Up to 500 files and 1 GiB** of uploads that haven't expired, per account. Over that, uploads return `422 file_quota_exceeded`.
- **60 uploads a minute, and 4 at once,** per account. Over that, `429 rate_limited` with a `Retry-After` header.
- **Uploads have no idempotency key.** An upload you retry is stored twice; the spare one expires on its own.
- **Allow time for large files:** an upload must finish within 5 minutes, and may not pause for more than 30 seconds (`408 upload_timeout`).

Only the account that uploaded a file can see it, send it or delete it. Another account's file ID is `404 file_not_found`.

## How the URLs are read

- **Each URL must be `https`,** and publicly reachable. iBubbl downloads it once, when the request arrives, and keeps its own copy. A signed or expiring URL only needs to work for a few minutes; once you have the `202`, it can expire.
- **Redirects** are followed, up to 3, as long as every hop is `https`.
- **The type** comes from the response's `Content-Type` header. When that is `application/octet-stream` (or missing), the URL's file extension decides instead, so `…/report.pdf` works.
- **Private and internal addresses are refused,** including `localhost`, private networks and cloud metadata addresses, at every hop.
- **The whole request fails if one file does.** Nothing is sent and no message is created, so you can fix the URL and send again with the same `idempotency_key`.
- **Downloads have a time limit:** all the files together get about 30 seconds, and a server that stops sending for 10 seconds fails the download.
- **The file name your contact sees** is the one the server gives in `Content-Disposition`, or else the last part of the URL's path (after any redirects): `…/visits/1042/front.jpg` arrives as `front.jpg`. See [File names](#file-names).

## File names

Your contact sees each file's name, most visibly on a PDF. iBubbl keeps the name you give:

- **Uploads:** the file name in the upload's `multipart` part.
- **URLs:** the server's `Content-Disposition` file name, or else the last part of the URL's path.

The name is cleaned before it is used: any folders, control characters and `/\:*?"<>|` are removed, it is cut to 100 characters before the extension, and the extension is always the file type's own. So `Invoice 1042.PDF` arrives as `Invoice 1042.pdf`, and a PNG at `…/photo.jpg` as `photo.png`. Two files with the same name in one message become `Invoice.pdf` and `Invoice (2).pdf`. With no usable name, iBubbl generates one.

The `filename` field on each of a message's `attachments` shows the name that was sent. It is `null` for files your contacts send you, and for files sent before names were kept (see the [Changelog](/changelog)).

## Supported files and limits

| Kind | Types | Largest file |
| ---- | ----- | ------------ |
| Images | JPEG, PNG, WebP, HEIC, HEIF | 25 MiB each |
| GIFs | GIF | 25 MiB each |
| Video | MP4, MOV (QuickTime) | 50 MiB (52,428,800 bytes) |
| PDF | PDF | 10 MB (10,000,000 bytes) |
| Audio | MP3, M4A (`audio/mp4`, `audio/x-m4a`), AAC | 25 MiB, sent on its own |

**For the whole message:**

- **Up to 10 files,** and **86 MB (86,000,000 bytes)** in all.
- **Any number of images and GIFs** can go together, within those totals.
- **Mixing kinds:** a message with several files that aren't all images can hold images, PDFs and videos (each within its own limit), plus **at most one audio file, and only an MP3 of 2 MB or less**. Other audio (M4A, AAC, or a larger MP3) must be sent on its own, in a message of its own.
- **Not supported:** other types, such as calendar invites (`.ics`), WebM or Ogg audio, SVG, Word documents and ZIP files.

Every file in a message that passes these rules goes out together with its caption. A combination that wouldn't is refused with `422 attachment_combination_not_supported` rather than sent without its text.

Attachments work only for one-to-one sends (`to` or `contact_id`). With `chat_guid` or `participant_phones` the request is refused with `422 validation_error`.

**Effects and replies can't be combined with attachments.** A request with `attachments` and `effect` or `reply_to_message_id` is refused with `422 validation_error` ("Effects and replies cannot be combined with attachments"). Send the files and the reply or effect as two messages.

## Captions and the first message

`body` is optional when you send `attachments`. If you include it, it's the caption.

**The first message to a contact must include text.** Messages can't open a new conversation with files alone, so a send with `attachments` and no `body` to a contact you've never exchanged a message with is refused with `422 first_message_needs_text`. Add a `body`. Once the contact has a message from you (sent, or still waiting to go out) or has sent you one, files without text are fine.

## What your contact sees

How the files arrive depends on how the message travels. `channel` on [Retrieve a message](/api-reference/messages/retrieve), and on the `message.*` [webhooks](/webhooks/events#the-channel-field), tells you which way it went once it's sent.

- **iMessage:** the caption and the files go out together, as one send: the caption appears first, then the files directly below it, as separate bubbles. A message without a `body` shows just the files.
- **SMS/MMS** (the contact isn't on iMessage):
  - **Up to 5 images, 10 MB in all,** go as one MMS with the caption. One video, or one audio file of 2 MB or less, also goes as one MMS.
  - **Anything larger or mixed** (more images, a PDF, other audio, or images with a video) goes as the caption first, then each file as a separate message, a couple of seconds apart. Carriers can deliver those messages out of order.
  - **PDFs can't be sent over plain SMS.** If the contact's phone only takes SMS/MMS, a message with a PDF fails, and you get [`message.failed`](/webhooks/events).
- **RCS** (an Android phone with RCS): the caption first, then **one file per message**, a second or two apart and in your order.

Your `attachments` array and the `202` are the same whichever way the message goes.

## Idempotency

The `attachments` list is part of the [idempotency](/idempotency) payload, **in order**: the URLs and file IDs exactly as you sent them. A retry with the same `idempotency_key` must send the same list in the same order; a different item, a missing one or a new order returns `409 idempotency_conflict`.

A retry that replays an accepted message returns the original response **without downloading or copying anything again**, even if the file at the URL has changed or the upload has expired since. To send a changed file, use a new key. To send the same upload to another contact, or again, use a new key too: it's a new message.

## Errors

A refused request creates no message, so its `idempotency_key` stays unused. Each attachment error names the file it's about by its position, starting at 0: `attachments[1]: attachment fetch answered 404`.

| `detail.error` | HTTP | Cause | What to do |
| -------------- | ---- | ----- | ---------- |
| `file_not_found` | 404 | A file ID in `attachments` isn't one of your uploads, or was deleted. | Upload the file again and send its new `id`. |
| `file_expired` | 422 | A file ID's `expires_at` has passed. | Upload the file again and send its new `id`. |
| `attachment_fetch_failed` | 422 | iBubbl couldn't download a URL: not `https`, the host doesn't resolve or is private, a non-`200` answer, more than 3 redirects, an empty file, or the download took too long. | Check the URL works from the public internet, then send again. |
| `attachment_too_large` | 422 | A file is over its kind's limit, or the files are over 86 MB in all. | Send a smaller file, or split the files across messages. |
| `unsupported_attachment` | 422 | A file's type isn't in the table above. | Convert it to a supported type. |
| `attachment_combination_not_supported` | 422 | The files can't go together, for example an M4A with a photo, or two audio files. | Send the audio in a message of its own. |
| `first_message_needs_text` | 422 | Files without `body` to a contact you've never exchanged a message with. | Add a `body`. |
| `validation_error` | 422 | The request's shape: an empty `attachments` list, more than 10 items, something that is neither an `https` URL nor a file ID (`file_` and 32 lower-case hex characters), `attachments` with `chat_guid` or `participant_phones`, `attachments` with `effect` or `reply_to_message_id`, or neither `body` nor `attachments`. | Fix the request. |
| `rate_limited` | 429 | Rare: iBubbl is downloading too many attachment sends at once. Comes with a `Retry-After` header (5 seconds). | Wait `Retry-After` seconds, then send the same request again with the same `idempotency_key`. |

Uploads have their own errors (`unsupported_attachment`, `attachment_too_large`, `file_quota_exceeded`, `upload_timeout`, `rate_limited`); see [Upload a file](/api-reference/files/upload#responses). The other send errors (opt-outs, limits and so on) work as for any send; see [Errors when sending](/guides/send-messages#errors-when-sending) and the [error catalog](/errors).
