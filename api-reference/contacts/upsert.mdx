### Create or update a contact

**Method:** `POST` | **Endpoint:** `/v1/contacts`

**Description:** Create a contact, or match an existing one, by phone number, and add tags. On an existing contact the optional fields are only filled where they are still empty: values a rep or an earlier call set are never overwritten here. To overwrite, use [Update a contact](/api-reference/contacts/update).

**Authentication:** API key in the `Authorization` header: `Authorization: Bearer ib_pk_<64 hex>`. Create keys in the dashboard under **Settings → API access**.

#### Request Body
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `phone` | string (E.164, e.g. `+14155551234`) | Yes | The contact's phone number, and the key it is matched on. Sending the same number again returns the same contact. Spaces, dashes and brackets are removed first, so `+44 7911 123456` is stored as `+447911123456`. A number with an extra digit after the country code, such as the trunk `0` in `+44 07911 123456`, is refused with `422 validation_error` and the number to send instead in `suggested`. |
| `first_name` | string, at most 128 characters | No | Only applied if the contact has no first name yet. |
| `last_name` | string, at most 128 characters | No | Only applied if the contact has no last name yet. |
| `email` | string, at most 254 characters | No | Must look like an email address (`name@domain.tld`, no spaces), or `422 invalid_email`. Only applied if the contact has no email yet. |
| `city` | string, at most 128 characters | No | Trimmed; blank counts as not sent. Only applied if the contact has no city yet. |
| `state` | string, at most 128 characters | No | Trimmed, and a 2-letter code is upper-cased (`ny` becomes `NY`). Only applied if the contact has no state yet. |
| `timezone` | string | No | IANA zone used for the contact's sending hours. Any real IANA zone, e.g. `America/New_York`, `Europe/London` or `Africa/Lagos`. If you leave it out, iBubbl infers the zone from the phone number: the area code in the US and Canada, the country and prefix elsewhere. Only applied if the contact has no timezone yet, so set it on the first call, before you send. |
| `tags` | array of strings, at most 20 | No | Tag names to add. Only ever adds: tags the contact has are kept and none are removed. A name matches an existing tag ignoring case and outer spaces (`vip` uses `VIP`); a new name creates the tag. Each name is 1–64 characters with no invisible characters. A newly added tag can start workflows with a "Tag added" trigger. |

Fields not listed above are rejected with `422 validation_error`, and the message names the field. Every value is checked before anything is saved, so a rejected call changes nothing.

<RequestExample>

```bash cURL
curl -X POST https://api.ibubbl.com/v1/contacts \
  -H "Authorization: Bearer $IBUBBL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "+14155551234",
    "first_name": "Sam",
    "last_name": "Rivera",
    "email": "sam@example.com",
    "city": "Brooklyn",
    "state": "ny",
    "timezone": "America/New_York",
    "tags": ["VIP", "Spring promo"]
  }'
```

```typescript TypeScript
const res = await fetch("https://api.ibubbl.com/v1/contacts", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.IBUBBL_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    phone: "+14155551234",
    first_name: "Sam",
    last_name: "Rivera",
    email: "sam@example.com",
    city: "Brooklyn",
    state: "ny",
    timezone: "America/New_York",
    tags: ["VIP", "Spring promo"],
  }),
  signal: AbortSignal.timeout(10_000),

const data = await res.json();
if (!res.ok) throw new Error(`${res.status} ${data.detail?.error}`);
// 201: a new contact was created; 200: an existing one matched.
console.log(res.status, data.id, data.tags);
```

```python Python
import os

import requests

API_KEY = os.environ["IBUBBL_API_KEY"]

res = requests.post(
    "https://api.ibubbl.com/v1/contacts",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={
        "phone": "+14155551234",
        "first_name": "Sam",
        "last_name": "Rivera",
        "email": "sam@example.com",
        "city": "Brooklyn",
        "state": "ny",
        "timezone": "America/New_York",
        "tags": ["VIP", "Spring promo"],
    },
    timeout=10,
)
data = res.json()
if not res.ok:
    raise RuntimeError(f"{res.status_code} {data['detail']['error']}")
# 201: a new contact was created; 200: an existing one matched.
print(res.status_code, data["id"], data["tags"])
```

**401 Unauthorized**
```json
{
  "detail": {
    "error": "unauthorized",
    "message": "Invalid or revoked API key"
  }
}
```
Other `message` values: `Authorization Bearer token required`, `API key required (use Authorization: Bearer ib_pk_…)`, `Invalid API key format`, `Customer account not found`.

**403 Forbidden**
```json
{
  "detail": {
    "error": "forbidden",
    "message": "Account is suspended"
  }
}
```
Your iBubbl account is suspended or cancelled (`message` is then `Account is cancelled`). Every API-key endpoint returns this.

**422 Unprocessable Entity**
```json
{
  "detail": {
    "error": "validation_error",
    "message": "company: Extra inputs are not permitted"
  }
}
```
Other `error` values:
- `validation_error` for a bad shape: `phone` not E.164 (`phone must be E.164 format (e.g. +14155551234)`), a field too long, or more than 20 tags.
- `validation_error` with `suggested`: `phone` has an extra digit after the country code, usually a trunk `0` (`+44 07911 123456`, `+234 0803 123 4567`). Nothing is saved. Send the `suggested` number instead:

```json
{
  "detail": {
    "error": "validation_error",
    "message": "phone: not in standard E.164 form; use the suggested number",
    "suggested": "+447911123456"
  }
}
```
- `invalid_email`: `'sam@example' is not an email address`
- `invalid_tag`: `A tag name needs 1–64 characters and no invisible characters (got '')`
- `invalid_timezone`: `timezone` outside the supported list.
- `duplicate_tag`: a tag name collides with an existing tag in a way iBubbl can't resolve. Rare; change the name.

**500 Internal Server Error**
```json
{
  "detail": {
    "error": "internal_error",
    "message": "The tag was deleted while it was being added; retry"
  }
}
```
Only if a tag is deleted in the dashboard twice while this call is adding it. Retry the request.
