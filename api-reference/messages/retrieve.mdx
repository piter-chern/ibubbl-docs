### Retrieve a message

**Method:** `GET` | **Endpoint:** `/v1/messages/{message_id}`

**Description:** Fetch one message by its ID to check its delivery state. Use it when you can't receive webhooks. To read many messages, or catch up after missed webhooks, use [List messages](/api-reference/messages/list).

**Authentication:** API key in the `Authorization` header: `Authorization: Bearer ib_pk_<64 hex>`. Create keys in the dashboard under **Settings → API access**.

#### Request Body
None. The path parameter `message_id` is the message's ID (a UUID), from the send response or a webhook event.

<RequestExample>

```bash cURL
curl https://api.ibubbl.com/v1/messages/8b3a4e72-1c2d-4e5f-9a0b-2c3d4e5f6a7b \
  -H "Authorization: Bearer $IBUBBL_API_KEY"
```

```typescript TypeScript
const messageId = "8b3a4e72-1c2d-4e5f-9a0b-2c3d4e5f6a7b";

const res = await fetch(`https://api.ibubbl.com/v1/messages/${messageId}`, {
  headers: { Authorization: `Bearer ${process.env.IBUBBL_API_KEY}` },
  signal: AbortSignal.timeout(10_000),
});

const data = await res.json();
if (!res.ok) throw new Error(`${res.status} ${data.detail?.error}`);
console.log(data.status, data.channel);
```

```python Python
import os

import requests

API_KEY = os.environ["IBUBBL_API_KEY"]

message_id = "8b3a4e72-1c2d-4e5f-9a0b-2c3d4e5f6a7b"

res = requests.get(
    f"https://api.ibubbl.com/v1/messages/{message_id}",
    headers={"Authorization": f"Bearer {API_KEY}"},
    timeout=10,
)
data = res.json()
if not res.ok:
    raise RuntimeError(f"{res.status_code} {data['detail']['error']}")
print(data["status"], data["channel"])
```

#### Responses
**200 OK**
```json
{
  "id": "8b3a4e72-1c2d-4e5f-9a0b-2c3d4e5f6a7b",
  "direction": "outbound",
  "created_at": "2026-11-05T15:04:10.112730Z",
  "status": "delivered",
  "to": "+14155551234",
  "line_id": "5f0c2a9e-7d41-4b8a-9e3c-6a1b2c3d4e5f",
  "line_number": "+14155550100",
  "body": "Hey Sam — quick check-in about your order.",
  "contact_id": "c8a1f4e2-3b9d-4f7c-a8e5-1d2c3b4a5e6f",
  "conversation_id": "3a4b5c6d-7e8f-9a0b-1c2d-3e4f5a6b7c8d",
  "conversation_kind": "one_to_one",
  "chat_guid": null,
  "channel": "imessage",
  "sent_at": "2026-11-05T15:04:12.381Z",
  "held_until": null,
  "held_reason": null,
  "effect": null,
  "link_preview": false,
  "reply_to_message_id": null,
  "attachments": [],
  "edited_at": null,
  "edit_count": 0,
  "edit_status": null,
  "unsend_status": null,
  "unsent_at": null
}
```
`direction` is `outbound` or `inbound`: an inbound message (for example the `message_id` of a `message.inbound` event) can be retrieved too, and then `status` is `delivered`, or `read` once it has been read in the dashboard, and `to` is the contact who sent it. `line_id` and `line_number` name the line the message was on (the one that sent it, or received it): the `id` and `phone_number` in [List lines](/api-reference/lines/list). `created_at` is when iBubbl recorded the message (UTC, microseconds, never changes). `status` is one of `queued`, `pending`, `sent`, `delivered`, `read`, `failed`, `expired`, `cancelled`. `channel` is how it went out (`imessage` or `sms`), or `null` before it is sent. For an inbound message, it is how the message arrived (`null` for messages received before iBubbl recorded it). `attachments` lists the message's files in order, each as `kind` (`image`, `gif`, `video`, `audio` or `file`), `mime_type` and `size_bytes`, for files you sent and files the contact sent you; it's `[]` when there are none. File contents and URLs aren't returned. An inbound file can show `size_bytes: 0` for a few seconds, until iBubbl has received it. `edit_status`, `edit_count` and `edited_at` say whether the message was [edited](/api-reference/messages/edit) and how often (your edits, or the contact's on an inbound message); `unsend_status` and `unsent_at` whether it was [unsent](/api-reference/messages/unsend), whole (`unsent`, and `body` is then `""`) or in part (`partly_unsent`). `status` doesn't change when a message is edited or unsent. `link_preview` is `true` for a message sent through the API with [`link_preview: true`](/guides/send-messages#send-a-link-with-a-preview-card); a message typed in the dashboard gets a card for its link without it, and shows `false`. See [Where it stands](/guides/editing-and-unsending#where-it-stands).

**401 Unauthorized**
```json
{
  "detail": {
    "error": "unauthorized",
    "message": "Invalid or revoked API key"
  }
}
```
Other `message` values: `Authorization Bearer token required`, `API key required (use Authorization: Bearer ib_pk_…)`, `Invalid API key format`, `Customer account not found`.

**403 Forbidden**
```json
{
  "detail": {
    "error": "forbidden",
    "message": "Account is suspended"
  }
}
```
Your iBubbl account is suspended or cancelled (`message` is then `Account is cancelled`). Every API-key endpoint returns this.

**404 Not Found**
```json
{
  "detail": {
    "error": "not_found",
    "message": "Message not found"
  }
}
```
Also returned for a malformed ID and for a message that belongs to another account.
