### Unsend a message

**Method:** `POST` | **Endpoint:** `/v1/messages/{message_id}/unsend`

**Description:** Take back a message you sent over iMessage, the way Undo Send works on an iPhone: within 110 seconds of sending. See [Edit, Undo Send and Cancel](/guides/editing-and-unsending).

**Authentication:** API key in the `Authorization` header: `Authorization: Bearer ib_pk_<64 hex>`. Create keys in the dashboard under **Settings → API access**.

**Rate limit:** 300 conversation actions per 60 seconds per account (edits, unsends, cancels, tapbacks, mark read and typing together, across all your API keys). Over that, you get `429 rate_limited` with a `Retry-After` header; see [Rate limits](/concepts/limits#rate-limits).

#### Request Body

None. The path parameter `message_id` is the `id` of a message you **sent**: from [Send a message](/api-reference/messages/send), or from [List messages](/api-reference/messages/list), where messages sent from the dashboard appear too.

<Warning>
**Never rely on Undo Send to retract sensitive information.** A recipient on an older iPhone, iPad or Mac keeps the original message, and anyone may have read it, copied it or seen it in a notification in the seconds before. See [What the recipient sees](/guides/editing-and-unsending#what-the-recipient-sees).
</Warning>

#### How it behaves

- **It's accepted first, applied second.** The answer is `202` with `unsend_status: "pending"`, and `body` is already empty. A few seconds later the message is gone from the recipient's conversation: [`message.unsent`](/webhooks/events#message-unsent) fires with `direction: "outbound"` and `scope: "message"`, and `unsend_status` becomes `unsent`.
- **If it doesn't land, the text comes back.** [`message.unsend_failed`](/webhooks/events#message-unsend-failed) fires, `unsend_status` becomes `failed`, and `body` returns: the recipient still has the message. Calling again tries once more, if the 110 seconds aren't up.
- **It's safe to call twice.** While the Undo Send is pending, or once it's done, calling again answers `200` with the message and changes nothing.
- **110 seconds.** Measured from `sent_at`. iMessage allows 2 minutes; iBubbl stops 10 seconds early so the Undo Send never arrives too late. After that, `422 unsend_window_expired`.
- **Not while an edit is on its way.** `409 edit_in_flight`: wait for `message.edited` (a few seconds), then unsend.
- **iMessage only.** A message that went out by SMS (`channel: "sms"`, RCS included) can't be unsent: `422 sms_not_supported`. One that hasn't gone out yet gets `422 not_sent_yet`: [cancel it](/api-reference/messages/cancel) instead.
- **One bubble at a time.** A text message, or a message that is one file and nothing else, is unsent whole. A message with files and text, or several files, shows as several bubbles and gets `422 multi_part`: unsending part of a message is available in the dashboard only, for now.
- **Messages with a link preview.** A message sent with [`link_preview: true`](/guides/send-messages#send-a-link-with-a-preview-card), or typed in the dashboard, goes out as two bubbles: the text and a preview card. Unsending it takes back both the text bubble and the card. A message sent without `link_preview` is one bubble.
- **Opted-out contacts don't block it.** An Undo Send only removes content, so it works whatever the contact's opt-out or block status. Groups work too.

  -H "Authorization: Bearer $IBUBBL_API_KEY"

```typescript TypeScript
const messageId = "8b3a4e72-1c2d-4e5f-9a0b-2c3d4e5f6a7b";

const res = await fetch(
  `https://api.ibubbl.com/v1/messages/${encodeURIComponent(messageId)}/unsend`,
  {
    method: "POST",
    headers: { Authorization: `Bearer ${process.env.IBUBBL_API_KEY}` },
    signal: AbortSignal.timeout(10_000),
  },
);

const data = await res.json();
if (!res.ok) throw new Error(`${res.status} ${data.detail?.error}`);
// 202: the Undo Send is on its way; 200: already unsent or being unsent.
console.log(res.status, data.unsend_status);
```

```python Python
import os
import urllib.parse

import requests

API_KEY = os.environ["IBUBBL_API_KEY"]

message_id = "8b3a4e72-1c2d-4e5f-9a0b-2c3d4e5f6a7b"

res = requests.post(
    f"https://api.ibubbl.com/v1/messages/{urllib.parse.quote(message_id, safe='')}/unsend",
    headers={"Authorization": f"Bearer {API_KEY}"},
    timeout=10,
)
data = res.json()
if not res.ok:
    raise RuntimeError(f"{res.status_code} {data['detail']['error']}")
# 202: the Undo Send is on its way; 200: already unsent or being unsent.
print(res.status_code, data["unsend_status"])
```

#### Responses
**202 Accepted**

The Undo Send is on its way. The body is the [message](/api-reference/messages/retrieve) with `unsend_status: "pending"`.

| Field | Description |
|-------|-------------|
| `body` | `""` at once (for a message with a link preview card, the link alone until the card is gone too). The text comes back if the Undo Send fails. |
| `unsend_status` | `pending` now; then `unsent` when it reaches the recipient, or `failed` if it doesn't. |
| `unsent_at` | When it was unsent (UTC); `null` until then. |

**200 OK**

The message is already unsent, or being unsent. The body is the message as it is; nothing new was sent.

**401 Unauthorized**
```json
{
  "detail": {
    "error": "unauthorized",
    "message": "Invalid or revoked API key"
  }
}
```
Other `message` values: `Authorization Bearer token required`, `API key required (use Authorization: Bearer ib_pk_…)`, `Invalid API key format`, `Customer account not found`.

**403 Forbidden**
```json
{
  "detail": {
    "error": "forbidden",
    "message": "Account is suspended"
  }
}
```
Your iBubbl account is suspended or cancelled (`message` is then `Account is cancelled`). Every API-key endpoint returns this.

**404 Not Found**
```json
{
  "detail": {
    "error": "not_found",
    "message": "Message not found"
  }
}
```
Also returned for a malformed ID and a message that belongs to another account.

**409 Conflict**
```json
{
  "detail": {
    "error": "edit_in_flight",
    "message": "An edit is being dispatched; wait for it to complete before unsending."
  }
}
```
An edit of this message hasn't reached the recipient yet. Wait for `message.edited` (usually a few seconds), then unsend. Nothing changed.

**422 Unprocessable Entity**
```json
{
  "detail": {
    "error": "multi_part",
    "message": "This message has more than one part (text and files, or several files), so it can't be unsent through the API."
  }
}
```
Nothing changed. The `error` is one of:

- `invalid_target`: the message is one you received. Only messages you sent can be unsent.
- `sms_not_supported`: the message went out by SMS (RCS included), where messages can't be unsent.
- `not_sent_yet`: the message is still `pending` or `queued`. [Cancel it](/api-reference/messages/cancel) instead.
- `not_unsendable`: the message failed, was cancelled or expired, or iMessage never confirmed it.
- `unsend_window_expired`: more than 110 seconds since `sent_at`.
- `multi_part`: the message has files and text, or several files. Unsending part of a message is available in the dashboard only.
- `no_eligible_line`: the line it was sent from is no longer active on your account (for example, it was moved to another account). Nothing was changed. Don't retry.

**429 Too Many Requests**
```json
{
  "detail": {
    "error": "rate_limited",
    "message": "Too many conversation actions; wait 12s (limit 300 a minute per account)."
  }
}
```
Wait the `Retry-After` header's seconds, then send the same request again.
