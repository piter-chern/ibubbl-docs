### Receive an event

**Method:** `POST` | **Endpoint:** `/v1/events/{token}`

**Description:** The URL a connected app (Recharge, your own system, or a no-code tool such as Zapier or Make) posts its events to. An event that matches an active workflow's "Webhook received" trigger starts a run. See [Inbound events](/inbound-events/overview) for setup.

**Authentication:** No API key. The `token` in the path (`ibev_` followed by 64 hex characters, copied from the event source in the dashboard) identifies the source. A signed source must also send its signature header: Recharge sends `X-Recharge-Hmac-Sha256`; a generic signed source sends `X-iBubbl-Signature: t=<unix seconds>,v1=<hex>`, an HMAC-SHA256 of `{t}.{raw body}` with the source's signing secret, no more than 5 minutes old. A secret-URL source sends no signature and is limited to 60 requests a minute.

#### Request Body
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| (the app's event) | object | Yes | The connected app's own payload, sent unchanged as JSON (or form-encoded), at most 256 KB. iBubbl doesn't require any fields; your workflow maps the ones it needs. The signature is checked against these exact bytes, so don't re-serialize the body. |

<RequestExample>

```bash cURL
# No API key: the token in the URL identifies the source.
# Sign the exact bytes you send, with the source's signing secret.
BODY='{"topic": "order/created", "customer": {"phone": "+14155551234", "first_name": "Sam"}}'
T=$(date +%s)
SIG=$(printf '%s' "$T.$BODY" | openssl dgst -sha256 -hmac "$IBUBBL_EVENT_SECRET" | awk '{print $NF}')

curl -X POST "https://api.ibubbl.com/v1/events/$IBUBBL_EVENT_SOURCE_TOKEN" \
  -H "Content-Type: application/json" \
  -H "X-iBubbl-Signature: t=$T,v1=$SIG" \
  --data-raw "$BODY"
```

```typescript TypeScript
import { createHmac } from "node:crypto";

// No API key: the token in the URL identifies the source.
const token = process.env.IBUBBL_EVENT_SOURCE_TOKEN;
const secret = process.env.IBUBBL_EVENT_SECRET ?? "";

// Serialize once, then sign and send that same string.
const body = JSON.stringify({
  topic: "order/created",
  customer: { phone: "+14155551234", first_name: "Sam" },
});
const t = Math.floor(Date.now() / 1000);
const v1 = createHmac("sha256", secret).update(`${t}.${body}`).digest("hex");

const res = await fetch(`https://api.ibubbl.com/v1/events/${token}`, {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "X-iBubbl-Signature": `t=${t},v1=${v1}`,
  },
  body,
  signal: AbortSignal.timeout(10_000),
});

const data = await res.json();
if (!res.ok) throw new Error(`${res.status} ${data.detail?.error}`);
console.log(data.runs_started);
```

```python Python
import hashlib
import hmac
import json
import os
import time

import requests

# No API key: the token in the URL identifies the source.
TOKEN = os.environ["IBUBBL_EVENT_SOURCE_TOKEN"]
SECRET = os.environ["IBUBBL_EVENT_SECRET"]

# Serialize once, then sign and send those same bytes.
body = json.dumps({
    "topic": "order/created",
    "customer": {"phone": "+14155551234", "first_name": "Sam"},
}).encode()
t = str(int(time.time()))
v1 = hmac.new(SECRET.encode(), f"{t}.".encode() + body, hashlib.sha256).hexdigest()

res = requests.post(
    f"https://api.ibubbl.com/v1/events/{TOKEN}",
    headers={"Content-Type": "application/json", "X-iBubbl-Signature": f"t={t},v1={v1}"},
    data=body,
    timeout=10,
)
data = res.json()
if not res.ok:
    raise RuntimeError(f"{res.status_code} {data['detail']['error']}")
print(data["runs_started"])
```

#### Responses
**200 OK**
```json
{
  "received": true,
  "runs_started": 1
}
```
Every request that passes the signature check gets 200, including one that starts no run (`runs_started: 0`), so the sending app never retries or disables the hook. The reason an event started nothing is recorded on the event source.

**403 Forbidden**
```json
{
  "detail": {
    "error": "invalid_signature",
    "message": "Signature verification failed."
  }
}
```
The signature header is missing or doesn't match.

**404 Not Found**
```json
{
  "detail": {
    "error": "not_found",
    "message": "No such event source."
  }
}
```
The token is malformed, unknown or revoked.

**413 Content Too Large**
```json
{
  "detail": {
    "error": "payload_too_large",
    "message": "Request body too large."
  }
}
```

**429 Too Many Requests**
```json
{
  "detail": {
    "error": "rate_limited",
    "message": "Too many events for this source; try again in a minute."
  }
}
```
Only a secret-URL source over 60 requests a minute while a workflow is listening on it. Without a listener, the extra events are dropped with 200.
