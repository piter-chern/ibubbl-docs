### Retrieve a lookup

**Method:** `GET` | **Endpoint:** `/v1/imessage-lookups/{lookup_id}`

**Description:** Fetch one of your iMessage lookups by ID, for example to read the answer to a lookup that was `pending`. Prefer the [`imessage_lookup.completed`](/webhooks/events#imessage-lookup-completed) webhook to polling: a pending lookup usually completes within seconds. See [Check iMessage availability](/guides/check-imessage-availability).

**Authentication:** API key in the `Authorization` header: `Authorization: Bearer ib_pk_<64 hex>`. Create keys in the dashboard under **Settings → API access**.

#### Request Body
None. The path parameter `lookup_id` is the `id` from [Look up a number](/api-reference/imessage-lookups/create) or from the webhook.

<RequestExample>

```bash cURL
curl https://api.ibubbl.com/v1/imessage-lookups/3e4f5a6b-7c8d-4e9f-8a1b-2c3d4e5f6a7b \
  -H "Authorization: Bearer $IBUBBL_API_KEY"
```

```typescript TypeScript
const lookupId = "3e4f5a6b-7c8d-4e9f-8a1b-2c3d4e5f6a7b";

const res = await fetch(`https://api.ibubbl.com/v1/imessage-lookups/${lookupId}`, {
  headers: { Authorization: `Bearer ${process.env.IBUBBL_API_KEY}` },
  signal: AbortSignal.timeout(10_000),
});

const data = await res.json();
if (!res.ok) throw new Error(`${res.status} ${data.detail?.error}`);
console.log(data.status, data.result, data.source ?? data.reason);
```

```python Python
import os

import requests

API_KEY = os.environ["IBUBBL_API_KEY"]

lookup_id = "3e4f5a6b-7c8d-4e9f-8a1b-2c3d4e5f6a7b"

res = requests.get(
    f"https://api.ibubbl.com/v1/imessage-lookups/{lookup_id}",
    headers={"Authorization": f"Bearer {API_KEY}"},
    timeout=10,
)
data = res.json()
if not res.ok:
    raise RuntimeError(f"{res.status_code} {data['detail']['error']}")
print(data["status"], data["result"], data["source"] or data["reason"])
```

#### Responses
**200 OK**

The lookup:

| Field | Type | Description |
|-------|------|-------------|
| `id` | string (UUID) | The lookup's ID. |
| `phone` | string | The number looked up, in E.164. |
| `contact_id` | string (UUID) or null | The contact with this number. |
| `status` | string | `pending`: one of your lines is asking Apple. `completed`: `result` is final and never changes. |
| `result` | string or null | `imessage`: the number can receive iMessages. `not_imessage`: it can't, as far as Apple confirms (Android, a landline, or an iPhone with iMessage turned off). `unknown`: it couldn't be checked; see `reason`. This is not a no. `null` while pending. |
| `source` | string or null | Where the answer came from: `recent_imessage` (an iMessage from your account was delivered to the number in the last 30 days), `failed_imessage` (an iMessage send to it failed as not on iMessage), `previous_lookup` (Apple answered under 30 days ago) or `lookup` (Apple was asked for this lookup). `null` when `result` is `unknown` or pending. |
| `reason` | string or null | Why `result` is `unknown`: `timeout` (no line could ask Apple in time, usually because your lines were busy sending), `lookup_failed` (Apple didn't answer) or `line_unavailable` (the line it was queued on stopped serving your account). Look the number up again later. `null` otherwise. |
| `checked_at` | string (ISO 8601 UTC) or null | When the answer was obtained: the delivery, the failed send, or Apple's answer. Older than `created_at` for an answer iBubbl already had. `null` when there is no answer. |
| `completed_at` | string (ISO 8601 UTC) or null | When the lookup completed. `null` while pending. |
| `created_at` | string (ISO 8601 UTC) | When you asked. |

**401 Unauthorized**
```json
{
  "detail": {
    "error": "unauthorized",
    "message": "Invalid or revoked API key"
  }
}
```
Other `message` values: `Authorization Bearer token required`, `API key required (use Authorization: Bearer ib_pk_…)`, `Invalid API key format`, `Customer account not found`.

**403 Forbidden**

`forbidden`: your iBubbl account is suspended or cancelled. `feature_disabled`: lookups have been turned off for your account (they are on for every account unless support turns them off).

**404 Not Found**

`not_found`: no lookup with that ID on your account. Also returned for a malformed ID and for one that belongs to another account.
