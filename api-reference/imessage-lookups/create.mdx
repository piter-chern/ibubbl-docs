### Look up a number

**Method:** `POST` | **Endpoint:** `/v1/imessage-lookups`

**Description:** Find out whether a number can receive iMessages. Use it before you send something that only works over iMessage, such as a voice memo, a message [effect](/api-reference/messages/send) or an [edit](/api-reference/messages/edit). Ordinary texts don't need it: iBubbl already sends them by SMS when iMessage isn't available (see [Lines and routing](/concepts/lines-and-routing#imessage-or-sms)). See [Check iMessage availability](/guides/check-imessage-availability).

**Authentication:** API key in the `Authorization` header: `Authorization: Bearer ib_pk_<64 hex>`. Create keys in the dashboard under **Settings → API access**.

**Rate limit:** 60 requests per 60 seconds per account, across all your API keys (a budget of its own). Asking Apple also uses your line's lookup budget: 50 an hour and 100 a day per line. Over either, you get `429` with a `Retry-After` header; see [Limits](/guides/check-imessage-availability#limits).

#### Request Body
| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `phone` | string (E.164, e.g. `+14155551234`) | Yes | The number to look up. Any country. If no contact has this number and iBubbl has to ask Apple, a contact is created, so your next send to it uses the answer. |

Any other field is rejected with `422 validation_error`.

import os

import requests

API_KEY = os.environ["IBUBBL_API_KEY"]

res = requests.post(
    "https://api.ibubbl.com/v1/imessage-lookups",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={"phone": "+14155551234"},
    timeout=10,
)
data = res.json()
if not res.ok:
    raise RuntimeError(f"{res.status_code} {data['detail']['error']}")

#### Responses
**200 OK**

Answered at once, from what iBubbl already knows about the number: an iMessage delivered to it from your account in the last 30 days (`source: "recent_imessage"`), an iMessage send to it that failed as not on iMessage (`failed_imessage`), or an earlier answer from Apple under 30 days old (`previous_lookup`). `status` is `completed`. No Apple query was made and no lookup budget was used. The fields are described on [Retrieve a lookup](/api-reference/imessage-lookups/retrieve#responses).

**202 Accepted**

iBubbl doesn't know yet, so one of your lines is asking Apple: `status: "pending"`. The answer usually comes within seconds and at most about 20 minutes later, by the [`imessage_lookup.completed`](/webhooks/events#imessage-lookup-completed) webhook and by [Retrieve a lookup](/api-reference/imessage-lookups/retrieve). Your sends always go first, so a line that is busy sending answers later. Sending the same number again while it is pending returns this same lookup (`202`, same `id`) and asks Apple only once.

**401 Unauthorized**
```json
{
  "detail": {
    "error": "unauthorized",
    "message": "Invalid or revoked API key"
  }
}
```
Other `message` values: `Authorization Bearer token required`, `API key required (use Authorization: Bearer ib_pk_…)`, `Invalid API key format`, `Customer account not found`.

**403 Forbidden**
```json
{
  "detail": {
    "error": "feature_disabled",
    "message": "iMessage lookups aren't enabled for this account. Contact support to turn them on."
  }
}
```
`feature_disabled`: lookups are on for every account, so this means they have been turned off for yours; email [support@ibubbl.com](mailto:support@ibubbl.com). `forbidden`: your iBubbl account is suspended or cancelled.

**422 Unprocessable Entity**
```json
{
  "detail": {
    "error": "invalid_phone",
    "message": "phone isn't a valid number for its country."
  }
}
```
`invalid_phone`: the number has the E.164 shape but isn't a valid number in its country, so nothing was looked up. `validation_error`: `phone` is missing or not in E.164 (it must start with `+` and the country code), or the body has another field.

**429 Too Many Requests**

Two codes, both with a `Retry-After` header in seconds. Nothing was queued; send the same request again after that long.
- `lookup_budget_exhausted`: every line that could ask Apple has used its lookup budget, 50 an hour and 100 a day (midnight to midnight, US Eastern) per line, shared with GoHighLevel **Check iMessage** steps. `Retry-After` is when the first of those lines frees a slot.
- `rate_limited`: more than 60 lookup requests in 60 seconds from your account.

**503 Service Unavailable**
```json
{
  "detail": {
    "error": "line_offline",
    "message": "None of your lines can look numbers up right now. Try again in a few minutes."
  }
}
```
Nothing was queued and no contact was created.
- `line_offline`: none of your lines is online to ask Apple. Try again in a few minutes.
- `no_active_line`: your account has no active line.
- `lookup_unavailable`: the lookup couldn't be started. Try again shortly.
